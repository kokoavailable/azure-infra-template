# Task History

This directory stores a chronological record of completed or materially advanced
project work.

Use task history to answer:

- What did we finish?
- What changed?
- How was it verified?
- What follow-up remains?
- Which troubleshooting or learning notes are related?

## Files

- [2026-05](2026-05.md)

## Entry Format

```text
## YYYY-MM-DD - <Task Name>

Status:

Changed:

Validation:

Follow-up:

Related:
```

## Boundaries

- Use `.codex/session-notes/current.md` for in-progress task context.
- Use task history for completed or checkpointed work.
- Use `docs/troubleshooting/` for failure diagnosis and recovery details.
- Use `docs/learning/inbox.md` for concepts the user actually struggled with.

Keep entries concise. Do not store secrets, credentials, tenant IDs,
subscription IDs, backend values, production identifiers, or personal data.
